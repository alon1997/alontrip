## 现在代码实际在做什么

点 Generate → `POST /optimize-route` → `plan_trip(...)`。查车不在本文件。

### 它收到什么

| 输入 | 含义 |
|------|------|
| 城市列表（1–4 座，有顺序） | 先玩完东京再去京都，中间不穿插 |
| 天数 2–14 | 必须 ≥ 城市数 |
| 已勾景点 id | 每座城至少一个，否则拒绝 |
| 住法 | 一城一家 / 可换酒店 / 用户指定每天住哪 |
| 可选：到达枢纽、离开枢纽 | 必须分别属于第一座城、最后一座城 |
| 首末日密度 | 到达日 / 离开日要**尽量少排景点**（见第三步）。`first_day_density` / `last_day_density` 各 `none` 或 `few`；四组合都合法 |

校验失败返回固定英文句子（前端按原文匹配，不能随便改措辞）。

它**不看**：营业时间。排点时把「一整天」的园（`suggested_duration_min` ≥ 360，迪士尼/USJ 等）单独占一天，不跟别的点混。其余点仍主要按个数分。查车之后 `schedule.py` 累加钟点：午饭约 12:00（1 小时）；切开时不留下 ≤15 分钟游览残段。晚饭 1.5 小时落在约 17:30–19:30，跟当天最后一个景点和回酒店时刻走，不卡死 18:00。

### 硬上限

最多 4 城；2–14 天；勾选超过「天数 × 5」个点只警告、不拒绝。

### 第一步：把总天数切给各城

对应代码 `_split_city_days`。

1. 每座城先分到 1 天。
2. 多出来的天数，按该城**已勾景点数量**比例分（最大余数法）。某城 0 个点不会走到这里（前面已经拒绝）。
3. 城市块连续：东京 3 天就是第 1–3 天，京都 2 天就是第 4–5 天。

例：东京 8 点、京都 4 点、5 天 → 东京 3 + 京都 2。

### 第二步：每座城内部，景点分到该城的几天

**有 DeepSeek 钥匙：** 这座城打一次模型（`deepseek-v4-flash`，思考关闭，超时 45 秒）。只给这座城的点、这座城的天数、住法、首末日 `none`/`few`。要它交 JSON：每天哪些点、每天住哪家。思考默认开着时会把 `max_tokens` 吃光，HTTP 200 却没有 JSON 正文（上海那次就是）；现在请求里带 `thinking: disabled`。

模型必须同时满足，否则**整座城作废**（别的城不受影响），改走规则。失败打 **error** 日志，不是「正常降级」：

- 天数必须刚好是这座城分到的天数，1…n 不缺不重
- 每个已勾点用恰好一次
- 每天至少 1 个点；只有 prompt 允许的到达/离开 `none` 那天可以是空数组
- 酒店 id 必须能在该城候选里对上
- 一城一家：每天必须同一家
- 用户指定住宿：模型不能改

DeepSeek 表验收通过后，**不再按个数重切首末日**（那会把模型的片区拆掉）。Python 只再做一刀：停留 ≥ 360 分钟的园独占一天。

**没有钥匙或模型失败：** `_group_city_pois` → `grouping.py` 里的 `RuleBasedGrouper`：

1. 按地理坐标聚类（最远点先当中心，再迭代，确定、不随机）
2. 把点挪一挪，让每天数量差 ≤ 1（**这一步会拆开「该在一起的片区」**）
3. 每一天内部：从这天景点的地理中心出发，最近邻连下去
4. 几天之间按「更北的天排前面」排序

然后 `planner.py` 再做两刀：首末日 `none`/`few` 切个数；停留 ≥ 360 分钟的园独占一天。切个数时按清单顺序挪点，**不再按片区**，所以外滩/陆家嘴/上海中心可能被拆到不同天。这条路径只在 DeepSeek 失败时走。

若这座城分到的天数 **多于** 景点数：每个点单独一天、均匀撒在这个城市块里，多出来的天是空的（只有酒店/赶路）。不会让同一景点出现两天。

### 第三步：首末日尽量少排（到达日赶路、离开日赶路）

产品原则：**第一天和最后一天不要排成普通观光日。** 下飞机、入住、赶车占掉大半天。

- `none` = **0 个**景点（只赶路 / 入住 / 去机场）。若这座城所有天都是 none（例如两天行程两头都选 none），景点又不能丢，则退回均匀分，不强行两天都空。
- `few` = **尽量少，不是硬卡 1 个。** 有中间天可塞时，优先只留 1 个；中间天已经到约 5 个/天（和规划页「天数 × 5」软上限同一量级）就把多出来的留给 few 那天。没有中间天时（典型：两天行程、勾了 4–5 个点、末日 none），few 那天会承担剩余全部点，绝不能因为「few=1」把点扔掉或硬塞进 none 的那天。

对应代码 `_rebalance_edge_days` / `_edge_target_counts`：先按第二天把点分匀，再按上面的规则切首/末日。均匀分点那一步本身并不优待首末日，「尽量少」只发生在这一步。

**接口：** First day / Last day 各 `none`·`few`。planner 用 `resolve_edge_modes` 得到两个模式，再算每天个数。四组合都合法。默认仍是 First = few、Last = none。

这座城只有 1 天、没邻居可塞：不硬清成 0，以免把这城唯一一天清空。

### 第四步：选酒店（仅规则路径；DeepSeek 成功时酒店已由模型给）

候选 = 该城目录青旅（`listed=1`）。只用直线距离，不查公交。

- **一城一家：** 对「还有景点的那些天」的地理中心，找距离之和最小的一家，整块都住它。某天 0 个点不参加打分。
- **可换酒店：** 看当天最后一个景点，找最近的一家。若离**前一天那家**不到 2 km，继续住前一家。某天 0 个点：沿用前一天的酒店；第一天就空：用全城已选点的中心找一家。
- **用户指定：** 每天必须覆盖 1…总天数，缺一天就拒绝。模型不得改。

### 第五步：拼成「每天一条链」（给查车用）

对应拼 `PlannedDay`；真正把枢纽换进链里是 `main.py` 的 `_build_day_chain`。

- 第 1 天早上酒店 = 第 1 天晚上那家（简化：不管你下午才 check-in）。
- 第 N 天早上酒店 = 第 N−1 天晚上那家（换城日早上还在上一城的酒店，晚上已经在下一城）。
- 有到达枢纽且第一天有景点：链为 `枢纽 → 酒店(入住约 20 分钟) → 景点… → 当晚酒店`。第一天 0 个景点：枢纽 → 酒店。没选枢纽：酒店 → 景点 → 酒店。中间天、最后一天不套入住段。
- 有离开枢纽：最后一天链的终点改成车站/机场；那天「当晚酒店」按早上那家报（并不真入住链尾酒店）。

链（第一天有枢纽且有景点）：

```
到达枢纽 → 当晚酒店（checkin）→ 景点1 → … →（离开枢纽或当晚酒店）
```

某天 0 个景点：起点直接连终点（机场→酒店，或酒店→车站）。

没选枢纽时仍是酒店→景点→酒店。

### 查车（不在 planner.py）

`main.py` 对链上每一对相邻点问车。城内按当地 09:00、换城按当地 16:00。直线 &lt; 800 m 当步行。

- **日本 / 韩国 / 香港：** SerpApi Google 公交。缓存命中不重打。旧缓存里「No timetable + 票价 0」会再查一次，仍没有就改成打车估价。
- **中国大陆：** 有 `AMAP_KEY` 走高德公交；没有钥匙或高德也空，用打车估价（**不打 Google**，空结果只会烧额度）。
- 金额出门一律 **USD**（日元/人民币按固定汇率折）。查不到公交写 `No public transit · taxi · $x · xx min`，不编地铁票。

查车用的 09:00 只是问「假如这点出发有哪些班」。结果页钟点由 `schedule.py`（前端 `ResultMap` 同步一份）另算：从 09:00 累加交通 + 停留；午饭约 12:00；晚饭约 17:30–19:30（1.5 小时），不卡死 18:00。

游览行上的 `ticket unknown` 是景点门票价缺失，不是公交。有票价的也折成美元。

### 晚饭在 18 点附近，不要卡死 18:00（已实现）

现在 `schedule.py` / `ResultMap` 晚饭落在大约 17:30–19:30：最后一个景点若在 17:20–19:30 结束，先吃饭再回酒店；更早就回酒店，再等到 17:30 吃饭。不再为了 18:00 把园里行程劈开。时长仍是 1.5 小时。

### 分点要按片区，不能只按个数均分

上海合理的一天例如：第 1 天外滩 + 陆家嘴 + 上海中心（江边同一片）；第 2 天迪士尼独占；第 3 天豫园 + 新天地（老城厢/淮海），不要把上海中心再塞进第 3 天。

现在规则路径会「每天点数尽量一样」再按清单切首末日，把同一片区拆开。待办：先按地理片区成团（距离近的点同一天），再考虑首末日 few/none 和全日园；DeepSeek 成功时也要用同一条片区规则校验，不合格就回规则，不要交一份拆片区的表。

### 排点还要看停留和吃饭，不能只看个数

`suggested_duration_min` ≥ 360 的园已经独占一天。午饭 1 小时、晚饭 1.5 小时要进「这一天还塞不塞得下」。营业时间随后用来避开闭馆。
